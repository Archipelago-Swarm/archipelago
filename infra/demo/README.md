# One-command demo

```
make demo                 # smoke plan: 150 ticks, train + validation + test episode, cut at ticks 40-90
make demo PLAN=demo       # 900-tick scenario: cut at 300, rejoin at 600, 6 train / 3 validation / 3 test episodes
make demo-build | demo-up | demo-run | demo-down      # the same steps one at a time
```

`make demo` = `run_demo.py all`: `docker compose --profile local up -d --build --wait` (coordinator, `node-01..04`,
api, web, proxy, grafana, timescaledb), wait for the API `/readyz`, log in with the dev token, `POST /v1/runs` (the mounted plan file is the plan; a single raw plan is named `default`),
poll until the run is terminal, fetch `GET /v1/runs/{id}/events`, write `artifacts/demo/<run_id>/`, then
`docker compose down -v` (always, also on failure; on failure the compose logs are saved first to
`artifacts/demo/logs-failed/`). Artifacts stay in place. Needs a Docker daemon and the CPU torch wheel host
(`download.pytorch.org`); proxy port via `PROXY_HTTP_PORT` (default 80).

## Artifacts (`artifacts/demo/<run_id>/`, generated by the pure module `artifacts.py`)

| File | Content |
|---|---|
| `summary.json` | modes, per-node final loss/updates/policy version/returns, peer accepted/rejected counts and reasons, bytes, offers (also over cut links), wall time, commit, image digests, seeds, per-episode mean returns by kind |
| `curves.csv` | per node and tick: loss, update_count, policy_version, world coverage, `return_<phase>` |
| `peer_decisions.csv` | offers and accept/reject decisions with reason, candidate score, bytes, validation seconds |
| `topology_snapshots.json` | links, poses, coverage and fault phase at up to 12 ticks (every link change, plus an even sample) |
| `node_timeline.json` | per node: version changes, offers, decisions, unavailable/killed; fault-phase intervals |
| `learning_curve.svg`, `coverage_return.svg`, `partition_timeline.svg` | stdlib-rendered charts (colour plus shape/dash encoding) |
| `run.json` | final run view and the plan used |

`artifacts.py` takes the recorded canonical events (shape of `apps/web/src/fixtures/partition_run.json`), so it is
tested offline (`tests/infra/test_demo_artifacts.py`). `run_demo.py` only talks to Docker and the API.

## Configuration

* Secrets are required, with no defaults, in `compose.yml` (`NODE_CONTROL_TOKEN PEER_TOKEN TELEMETRY_TOKEN
  COORDINATOR_TOKEN COORDINATOR_ADMIN_TOKEN ARCHIPELAGO_API_TOKEN GRAFANA_ADMIN_PASSWORD`). `infra/compose/local.env`
  holds DEV-ONLY values used by `make demo`; a deployment uses `infra/compose/.env` (see `.env.example`).
* Plans: `plans/smoke.json`, `plans/demo.json` (coordinator `Plan` model), mounted read-only at `/plans` and selected by
  `COORDINATOR_PLAN_FILE=/plans/${DEMO_PLAN}.json` (A9). `battery_scale` (>= 4, A13) and `n_targets` (0, so an episode
  cannot end before the cut) are world settings in the compose env (`DEMO_BATTERY_SCALE`, `DEMO_N_TARGETS`) because the
  coordinator `Plan` has no such field yet.
* Networks follow A12 (`tests/infra/test_compose.py`). Only the proxy publishes ports.

## Memory limit (A16)

Node `mem_limit` is a PROVISIONAL 1g (the CUDA-wheel peak was about 686 MiB; the CPU-wheel image is unmeasured).
Procedure on a Docker host: `make demo-up PLAN=demo && infra/demo/measure_mem.sh demo`. It samples `docker stats` during the
run, reads `VmHWM` (peak RSS) from `/proc/1/status` in each node container, and applies the rule
**limit = 1.5 x peak RSS rounded up to a multiple of 64 MiB** (`measure_mem.sh --rule <peak_mib>`, tested). For example a
686 MiB peak gives 1088 MiB, so 1g would already be too small for that peak.

## Tests

* offline: `uv run pytest tests/infra -q -m "not docker"` (artifacts, driver against a fake API, plans through the
  coordinator model, compose via `docker compose config` and YAML, Dockerfile pins vs `uv.lock`, memory rule).
* Docker tier (CI): `uv run pytest tests/infra -q` (`test_demo_stack.py` runs the smoke plan end to end).
* No-Docker live smoke: `uv run pytest tests/e2e -q` (coordinator + four node processes; see `tests/e2e/procs.py`).
